# 숫자야구 추가 + 홈 화면 분류별 묶음

작성일: 2026-10-25
상태: 설계 승인됨, 문서 검토 대기

## 1. 목표

새 게임 3종(숫자야구 → 딱지치기 → 장기)을 하나씩 추가하는 계획의 첫 번째다. 이 문서는 숫자야구와, 게임이 15개로 늘어나는 것에 대비한 홈 화면 개편을 다룬다. 둘은 한 번에 배포한다(홈의 "혼자 하는 퍼즐·도구" 묶음이 숫자야구 없이는 어색하다).

배경: 검색 유입의 대부분이 게임 페이지(윷놀이·알까기)로 들어오고, 애드센스 심사는 게임 페이지의 본문 가치를 본다. 새 게임 페이지도 처음부터 게임 아래에 규칙·요령·AI 설명·FAQ를 함께 둔다.

## 2. 확정 요구사항

| 항목 | 결정 |
|---|---|
| 모드 | 혼자 하기(컴퓨터 숫자 맞히기), AI 대결(쉬움·보통·어려움), 온라인 대전(방 코드) |
| 한 화면 2인 대전 | 넣지 않음 (한 기기에서 서로의 비밀 숫자를 숨기기 어색함) |
| 자릿수 | 3자리 기본, 4자리 선택 |
| 숫자 | 1~9, 자리마다 서로 다른 숫자 (3자리 504가지, 4자리 3,024가지) |
| 대결 승패 | 번갈아 부르고, 선공이 맞히면 후공에게 마지막 한 번. 둘 다 맞히면 무승부, 후공이 먼저 맞히면 후공 승 |
| 선공 | AI 대결은 첫 판 사람 선공, 이후 판마다 번갈아. 온라인은 방장 선공, 재대결마다 번갈아 |
| 온라인 비밀 숫자 | 서버가 보관·판정 (클라이언트로 상대 숫자를 보내지 않음, 게임 종료 때만 공개) |
| 주소 | `/number-baseball`, `/en/number-baseball` |
| 홈 배치 | 분류별 묶음 (한국 전통 놀이 / 두뇌 대결 / 혼자 하는 퍼즐·도구) |

## 3. 비목표 (YAGNI)

- 숫자 메모판(제외한 숫자 표시) — 필요해 보이면 나중에
- 온라인 턴 제한 시간 — 숫자야구는 `TURN_TIMER_GAMES`에 넣지 않는다
- 0을 쓰는 규칙, 5자리 이상
- 한 화면 2인 대전과 "가림 화면"

## 6. 숫자야구 게임

### 화면과 흐름
- 모드 선택: 혼자 하기 → 자릿수 → 시작 / AI 대결 → 자릿수 → 난이도 → 내 숫자 정하기 → 시작 / 온라인 대전 → 방 만들기(자릿수) 또는 코드 입장 → 각자 숫자 정하기 → 시작
- 입력: 화면 숫자판(1~9, 지우기, 확인)과 키보드. 이미 고른 숫자는 흐리게 표시해 중복 선택을 막고, 자릿수가 다 차야 확인이 눌린다.
- 혼자 하기: 기록을 쌓아 "1S 1B", "아웃"으로 표시. 시도 횟수와 자릿수별 최고 기록(브라우저 저장, try/catch)을 보여준다.
- 대결: 내 숫자를 내 화면에만 작게 표시. 기록은 "내가 부른 숫자" / "상대가 부른 숫자" 두 칸(휴대폰은 위아래). 끝나면 양쪽 숫자 공개, 결과 창(다시 하기 / 나가기).
- 판정 표시 배지는 텍스트 대비 기준(WCAG AA)을 맞춘다.

### 규칙 함수 (클라이언트·서버 공통 정의, 각자 구현)
- `isValid(n, digits)`: 길이가 digits, 각 자리 1~9, 중복 없음
- `score(secret, guess)` → `{ strikes, balls }`
- 서버(`worker/baseball.js`)와 클라이언트가 같은 결과를 내는지 테스트로 확인한다(같은 입력 표로 양쪽 검사).

### AI (`AI 대결`에서 AI의 비밀 숫자는 무작위)
- **쉬움**: 바로 앞 판정 하나에만 맞는 숫자 중 무작위(그 전 단서는 잊는다). 이미 부른 숫자는 다시 부르지 않는다.
- **보통**: 지금까지의 모든 판정에 맞는 후보 중 무작위.
- **어려움**: 후보마다 "부른 뒤 남는 후보 수의 기댓값"을 계산해 가장 작은 숫자를 부른다. 첫 수는 무작위(대칭이라 결과가 같고, 4자리 계산 비용을 피한다).
- 난이도 간 차이가 실측으로 분명하지 않으면 쉬움을 더 약하게 조정한다.

## 7. 온라인 대전 (서버 판정)

원칙: 비밀 숫자는 DO 저장소의 별도 키(`secrets`)에만 둔다. 공개 상태(`state`)와 어떤 브로드캐스트에도 상대 숫자를 싣지 않고, 게임이 끝날 때만 공개한다.

- **방 만들기**: `initialState = { digits, phase: 'setup', first: 'black', history: [], ready: {} }`
- **`secret` 메시지** `{ secret }`: 상태가 playing이고 phase가 setup이며 자기 숫자가 아직 없을 때만. 형식 검사 후 `secrets[color]`에 저장, `ready[color] = true`. 양쪽에 `{ type: 'bb_ready', color, phase, turn }`만 알린다. 둘 다 정하면 `phase: 'playing'`, `turn = first`.
- **`guess` 메시지** `{ seq, guess }`: seq·차례·phase(playing/final)·형식 검사 후 상대 숫자로 판정, `history`에 `{ color, guess, strikes, balls }` 추가.
  - 선공이 다 맞힘 → `phase: 'final'`, 후공 차례
  - phase final에서 후공이 다 맞힘 → 무승부, 못 맞힘 → 선공 승
  - phase playing에서 후공이 다 맞힘 → 후공 승
  - 그 밖에는 차례만 넘김
  - 양쪽에 `{ type: 'bb_guess', color, guess, strikes, balls, seq, turn, phase, result?, secrets? }`. `secrets`는 끝났을 때만.
- **재접속**: `joined`에 공개 상태와 함께 **자기 숫자만**(`secret`) 싣는다.
- **재대결**: `secrets` 비우고 상태 초기화, `first`를 바꾼다. **나가기**: `secrets`도 비운다.
- **거부**: 형식 오류·차례 아님·단계 아님은 기존과 같은 `rejected` 메시지(공개 상태만 포함).
- 구현: `worker/baseball.js`에 순수 함수(`isValid`, `score`, `applySecret`, `applyGuess`), `room.js`는 메시지 분기와 저장만.
